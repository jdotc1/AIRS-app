# Owned two-FDE witness preparation

Source preparation only. No build_case invocation, generated bytes, CFI parser,

## Reuse and independent syntax

prepare.py reuses tests/test_dwarf_cfi.py's original literal CIE and record helper,
tests/test_rbit_x_candidate.py's small typed image helper, and AIRS's existing
FunctionRange/Section/UnwindEntry/UnwindTable types. It does not create another
CFI decoder, invoke a compiler or import MacScope internals. Existing MacScope-
derived instruction components are reused through AIRS, unchanged.

The local unsupported program is exactly 0x0a 0x0b: balanced
DW_CFA_remember_state / DW_CFA_restore_state. Both take no operands; the pair saves
then restores the current CFA/register rules. See the primary DWARF committee
clarification https://dwarfstd.org/issues/230103.1.html and the official compiler
opcode definitions https://gnu.googlesource.com/gcc/+/refs/heads/releases/gcc-6/include/dwarf2.def.
AIRS currently refuses opcode 0x0a rather than evaluating these semantics. This
packet does not request that instruction support be added. It avoids a truncated
operand stream masquerading as local unsupported semantics.

## Fixed source layout and offset domains

Every case has two independent eight-byte leaf functions, each NOP; RET:
[0x1000,0x1008) and [0x1008,0x1010), with LC_FUNCTION_STARTS authority in the typed
fixture. __eh_frame preferred VM starts at 0x1400; file offset is after sixteen
code bytes. The one shared CIE is at section offset zero. Each FDE has a backward
CIE pointer and signed PC-relative 64-bit start plus unsigned 64-bit span. Compact
DWARF low24 fields refer to exact FDE section offsets, not VM/file offsets.

For the ordinary supported CIE, source-derived FDE offsets are 20 and 46; a shared
CIE with the two extra unsupported bytes shifts them to 22 and 48. The builder
records its calculated offsets/ranges for comparison against these independent
source predictions in a future run. No observed input digest, UUID or measured output is claimed. The typed image
uses explicit placeholder digest strings only to permit strict report serialization;
they are not observed provenance or a full Mach-O identity. These typed helpers do not establish a full Mach-O file parser result.
